# Case Net — Local Fictional Internet

## Purpose

Case Net is a native investigation instrument for rendering websites that are authored case artifacts. It is not a general browser and has no public-internet fallback.

Every canonical page, link, search term, visual identity, and clue reveal comes from the active immutable `CaseDefinition`. Player visits, history, bookmarks, and discoveries are written to the separate persisted `CasePlayerState` through deterministic case-engine actions.

## Offline boundary

The implementation deliberately does not contain:

- `WebView`;
- arbitrary HTML or JavaScript;
- an editable address or URL field;
- HTTP requests or remote search;
- real-URL navigation;
- reload, share, download, or open-in-browser behavior;
- a remote image URI fallback.

Fictional hosts must omit a scheme and end in the reserved `.invalid` domain. Links are structured `{ targetSiteId, targetPageId }` references. Images are bundled native asset IDs resolved by `case-content/internetMediaRegistry.ts`; an unknown asset renders a local missing-asset treatment instead of requesting a network resource.

## Authored definition

`CaseDefinition.investigation.internet.sites` contains each site's:

- stable site ID and home page ID;
- optional closed unlock condition;
- unique visual identity ID;
- `.invalid` host, display name, mark, and tagline;
- layout family, typography treatment, shape language, and six-color palette;
- typed pages, blocks, local links, search terms, and evidence reveals.

Supported page blocks are headings, paragraphs, quotes, notices, local images, metrics, lists, community posts, profiles, and products. These are rendered by native React Native components in `FictionalSitePage`; no authored markup is executed.

The identity contract supports newsroom, community, market, institutional, personal, and broadcast families. Validation rejects reused identity definitions so separate sites cannot silently share the same visual skin.

## Deterministic player state

`CasePlayerState.fictionalInternet` persists only progress:

```ts
{
  currentLocation: { siteId, pageId } | null,
  history: Array<{ siteId, pageId }>,
  historyIndex: number,
  visitedPageKeys: string[],
  bookmarkedPageKeys: string[],
}
```

Page keys are generated by `createFictionalPageKey`. Opening a page truncates forward history, appends one structured location, records the visit, and discovers only that page's authored `revealsEvidenceIds`. Back and forward move over the saved local history without adding entries. Bookmark changes are idempotent.

All updates use `transitionCase`; they increment deterministic turns and emit domain events without timestamps. Invalid sites, pages, locked sites, unavailable history, and briefing-phase access return typed errors while preserving the original state.

The Zustand session store currently persists this state under schema version 4. Its migration gives version 1 and 2 sessions an empty Case Net state while preserving existing evidence progress; version 3 adds the later Evidence Board state without altering Case Net history.

## Local search

`searchFictionalInternet` performs normalized in-memory matching over available authored sites and pages. It searches only identity copy, fictional hosts, page titles, page descriptions, and explicit search terms. It cannot broaden a query to a remote service.

The Case Net index provides three local views:

- authored available-site index;
- saved page keys;
- deterministic visit history.

The search input is labeled as an archive index, not presented as an address bar.

## Native routes

```text
/investigation/internet             Case Net index/search/saved/history tool
/internet/[siteId]/[pageId]         Full-screen local page viewer
```

The viewer uses fixed game controls for close, local history, bookmark, and local index. The location strip is read-only and labels the page as an archived node. Site-to-site links remain inside the same structured engine and route boundary.

## Validation

`validateCaseDefinition` checks:

- unique site, page, block, link, and identity IDs;
- reserved `.invalid` host syntax;
- valid colors and positive local image aspect ratios;
- valid home pages and local link targets;
- valid unlock conditions;
- valid page-authored evidence IDs;
- non-empty identity and page content;
- visual identity uniqueness across the case.

CASE 001 registers six production sites using all six native layout families. The two additional sites in `verificationCase.ts` remain test-only fixtures and are never registered as playable content.

## Verification

The engine suite covers reserved offline hosts, unique identities, local search, page-authored clue discovery, visit history, back/forward behavior, bookmarks, JSON serialization, and rejection of real hosts and duplicate identities.
